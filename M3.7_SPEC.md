# M3.7_SPEC.md

Coach Mode v2 (Prescriptive Optimizer) + Long-Term Activity Log + Trend Analytics + Multi-Mascot Variant System. Issued at: M3.6 complete (overnight build of bug fixes + base Coach Mode + personalization foundation). Goal: turn Coach Mode from "daily insight commentary" into "prescriptive holistic optimizer" with year-plus historical context.

---

## Vision

Coach Mode v2 is the brain. It reads:
- Everything the user has logged (workouts, fasts, hydration, learning, schedule adherence) over the entire history
- HealthKit signals (steps, active calories, exercise minutes, resting HR, HRV, sleep, body weight if available)
- The user's stated goals
- The user's motivation style preference
- The current date, weather, location (Okinawa heat matters), schedule density

It produces:
- **Today's workout prescription** (specific lift template, basketball intensity, swim plan, or rest day) surfaced in TrainView as "Today's prescribed workout" the user can accept, modify, or override
- **Hydration target adjustment** (e.g., +24oz today because forecast is 92F + you have a swim block)
- **Schedule optimization suggestions** (e.g., "you've shifted lifts from Wed to Thu 4 weeks running; want to update the schedule?")
- **Daily optimization insight** (the existing Coach card from M3.6, now richer with prescriptive backbone)
- **Weekly programming pass** (every Sunday: looks at the week ahead, prescribes the volume distribution)

For wife: the killer feature is "I open the Train app, today's workout is already there, I tap accept, I do it, I'm done thinking." Removes the cognitive load of programming.

## Architecture Changes

### Long-term log persistence (already partially built)

SwiftData with CloudKit already persists data forever in user's iCloud. M3.7 makes this explicit and bulletproof:

1. Add explicit retention policy: never auto-delete session rows. Confirm by audit. If any cleanup code exists, remove it.
2. Add `ActivityArchive` summary table: rolled-up daily metrics (one row per user per day) that survive even if individual sessions are corrupted/migrated. Includes total volume, fasting hours, hydration oz, learning minutes, mascot dominant state, master metric.
3. Daily background job (BGAppRefreshTask) writes to ActivityArchive at end of day.
4. Backup/export: Settings -> Data -> Export full history as JSON (includes all sessions + ActivityArchive). Add as a tested round-trip (already exists for M1 import/export, extend to cover new entities).
5. Cloud backup verification: after first 30 days of use, Settings -> Data -> "Verify CloudKit sync" runs a sanity check showing what's synced vs local-only.

### Trend Analytics Service

New `TrendAnalyticsService` reads history and produces:
- Daily/weekly/monthly aggregates per domain
- Pattern detection (e.g., user trains 4.2x/week on average, dropped to 2.8x last 2 weeks)
- Streak history (longest streaks, current streaks, freeze usage rate)
- Adherence trends (master metric over 7/30/90 days)
- Hydration vs activity correlation
- Sleep vs HRV vs adherence correlation
- Volume progression in lifts (week-over-week, month-over-month)

API:
```swift
final class TrendAnalyticsService {
    func dailyAdherence(over: DateRange) -> [Date: Double]
    func volumeProgression(domain: TrainingDomain, over: DateRange) -> [Date: Double]
    func patternsDetected(over: DateRange) -> [DetectedPattern]
    func summaryForCoach(over: DateRange) -> CoachContextHistorical
}
```

`summaryForCoach` is the key method — produces a compact (~500 tokens) historical context that feeds into Coach Mode prompts. Without this, Coach can only react to today; with it, Coach can prescribe based on patterns.

### CoachService v2 expansion

Add three new generation modes alongside the existing daily insight:

```swift
final class CoachService {
    // existing
    func generateDailyInsight(for userProfile: UserProfile) async -> CoachInsight

    // new in M3.7
    func prescribeTodaysWorkout(for userProfile: UserProfile) async -> PrescribedWorkout
    func suggestScheduleOptimizations(for userProfile: UserProfile, lookback: Int = 30) async -> [ScheduleSuggestion]
    func generateWeeklyProgrammingPass(for userProfile: UserProfile) async -> WeeklyProgram
    
    // helper
    func gatherFullContext(userProfile: UserProfile) -> CoachContextV2
}
```

CoachContextV2 includes everything CoachContext (M3.6) had, plus:
- TrendAnalyticsService.summaryForCoach() output
- User's stated goals (new field on UserProfile)
- Equipment available (gym, home, bodyweight, full equipment, etc.)
- Time available today (in minutes, derived from open schedule slots)
- Weather/temperature (HealthKit ambient if available, otherwise stub for v1)

### New SwiftData entities

```swift
@Model final class PrescribedWorkout {
    var generatedAt: Date
    var forDate: Date
    var workoutType: String  // lift_a | lift_b | basketball | swim | rest | custom
    var template: String     // JSON-encoded sets/reps/exercises for lifts; intensity zones for basketball/swim
    var rationale: String    // why this workout today, in user's voice
    var status: String       // suggested | accepted | modified | skipped | completed
    var sessionID: UUID?     // FK to actual session if accepted
    var tokenUsage: Int
}

@Model final class ScheduleSuggestion {
    var generatedAt: Date
    var description: String  // human-readable suggestion
    var changeType: String   // shift_block | add_block | remove_block | merge | split
    var changePayload: String  // JSON of the proposed change
    var status: String       // pending | accepted | dismissed | snoozed
    var rationaleData: String  // pattern data backing the suggestion
}

@Model final class WeeklyProgram {
    var weekStartDate: Date
    var generatedAt: Date
    var programJSON: String  // 7-day plan with prescribed workouts per day
    var status: String       // active | superseded | completed
    var coachInsights: String  // narrative explanation
}

@Model final class ActivityArchive {
    var date: Date  // unique per user per day
    var workoutVolumeTotal: Double
    var workoutCount: Int
    var fastingHours: Double
    var hydrationOz: Double
    var learningMinutes: Int
    var dominantMascotState: String
    var masterMetric: Double  // 0.0-1.0
    var stepsHK: Int?
    var activeCaloriesHK: Double?
    var exerciseMinutesHK: Int?
    var sleepMinutesHK: Int?
    var hrvAvgHK: Double?
    var restingHRHK: Int?
}

@Model final class DetectedPattern {
    var detectedAt: Date
    var patternType: String  // schedule_drift | volume_decline | hydration_correlation | sleep_impact | etc.
    var confidence: Double   // 0.0-1.0
    var description: String
    var actionableSuggestion: String?
    var dismissed: Bool
}
```

### Goals on UserProfile

Add fields:
- `primaryGoal: String?` — free text (e.g., "build muscle, stay sharp on the court, learn Japanese conversational")
- `secondaryGoals: [String]` — array
- `equipmentAccess: String` — "gym" | "home_full" | "home_minimal" | "bodyweight" | "outdoor"
- `weeklyTrainingTargetSessions: Int` — default 5
- `restrictions: [String]` — injuries, dietary, time, etc.

These feed into Coach prescriptions.

## Multi-Mascot Variant System

Currently the app has 8 PNG assets named MascotNeutral, MascotThirsty, etc. M3.7 adds support for multiple mascot variants per user, then ships a female variant for wife.

### Architecture

Add `mascotVariant: String` field to UserProfile. Default "ninja_male". Allowed values: ninja_male, ninja_female, custom (future).

Refactor asset naming:
- Move existing PNGs from MascotNeutral.imageset → NinjaMale_Neutral.imageset (etc.)
- Add NinjaFemale_Neutral.imageset (etc.) with new PNGs (user generates via Gemini, see prompt set in M3.7_MASCOT_PROMPTS.md companion doc)

CharacterState.assetName(for variant:) helper:
```swift
extension CharacterState {
    func assetName(for variant: String) -> String {
        switch variant {
        case "ninja_male": return "NinjaMale_\(self.suffix)"
        case "ninja_female": return "NinjaFemale_\(self.suffix)"
        default: return "NinjaMale_\(self.suffix)"  // fallback
        }
    }
}
```

CharacterView reads userProfile.mascotVariant on init and uses the variant-aware asset name.

Settings -> Mascot lets user pick which variant they want. Wife installs the app, picks "ninja_female" during onboarding.
