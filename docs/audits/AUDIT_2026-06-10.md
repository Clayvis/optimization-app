## Executive Summary

Overall health: **B+**. This is a mature, disciplined solo codebase: 662 tests passing, zero warnings on all targets, typed errors, justified `try?` sites, a real recovery ladder, centralized timezone handling, and a non-destructive retention model that is actually honored. There are **no Critical findings**. The weaknesses are the predictable cost of a no-frameworks multi-target app that grew an Engagement layer fast: the same business rules are re-implemented across targets and have begun to **drift**, the **watch app already shows different numbers than the phone** for the same day, and the only CI is an archive workflow that **never runs the test suite**.

- **Top 3 risks:** (1) the watch home screen computes the master metric with wrong rules (32 oz bottle = hydration done, hardcoded 4 domains, no travel/sick grace) — a user-facing correctness bug; (2) launch-time keychain migration silently reverts the user's "device-only API key" privacy opt-out; (3) watch complication providers open a fresh CloudKit-mirrored `ModelContainer` per timeline entry (up to 73 store opens per refresh) — a battery drain.
- **Top 3 opportunities:** (1) collapse the duplicated hydration/learning/streak rules into single shared definitions — the single highest-leverage change, it both fixes the drift and de-risks every future edit; (2) make the parity-critical `ProtocolGoalSnapshot` the one tally everyone uses, including the watch; (3) add a CI test gate so the 662-test green bar is enforced, not aspirational.

## Repo Map

- **Stack:** Swift 6 (strict concurrency), SwiftUI, SwiftData + CloudKit, HealthKit, ActivityKit, WidgetKit, WatchConnectivity, Anthropic API direct. xcodegen-generated project (`project.yml` is source of truth). No third-party packages.
- **Targets:** iOS app, watch app, watch Complications extension, Live Activity extension, unit tests. Extensions share iOS sources via per-file path lists in `project.yml`.
- **Size:** ~29.7k production LOC / 201 Swift files; 9.8k test LOC / 74 files; 138 commits; 14 milestone tags through `v1.0.0-rc3`.
- **Key dirs:** `Models/` (50 @Model + schema files), `Services/` (28 system-facing services), `Modules/` (90 files; `Engagement/` is the largest and newest), `Views/` (10 large screens; `TodayView` 801 lines), watch + extension targets.

## Audit Report (findings by severity)

### High
1. **Watch app tally uses different rules than every other surface** (fact) — `PersonalOptimizationWatch/Views/IdleHomeWatchView.swift:220-242`. `todayTally()` re-implements the protocol tally with: hydration = `profile.bottleSizeOz` (32 oz default) instead of the day-type floor (64-96 oz); learning = `jp+guitar>=30` instead of the per-module-or-total rule; scheduled count hardcoded to 4; travel/sick grace ignored. `ProtocolGoalSnapshot` exists as the single source of truth but is shared only to the complications target, not the watch app. Consequence: watch, complication, and phone can show three different completion counts for the same day.
2. **Launch keychain migration reverts the device-only opt-out** (fact) — `PersonalOptimizationApp.swift:100` → `KeychainService.migrateApiKeyToICloudSynced()` runs unconditionally; its probe matches the `...ThisDeviceOnly` item the Settings opt-out writes, then rewrites the key with the default `iCloudSync: true` and deletes the device-only item. The user's explicit "do not sync my API key" choice is silently undone on the next launch.
3. **Complication providers open a `ModelContainer` per timeline entry** (fact, **verified High**) — `FastCountdownTimelineProvider.swift`, `HydrationComplication.swift`, `CurrentBlockTimelineProvider.swift`, `ProtocolGoalComplication.swift`, `MascotComplication.swift`. `getTimeline` calls `makeEntry` once per stride entry, and each `makeEntry` opens a fresh CloudKit-mirrored container: up to 73 (FastCountdown), 25, 25, 13, 13 opens per refresh. Battery and latency cost on every watch-face timeline build.
4. **No CI runs the test suite** (fact) — only Xcode Cloud's archive workflow exists; the 662-test green bar and zero-warning gate are enforced by hand. A regression can reach `main` and a TestFlight build undetected.
5. **DurabilityHeadlineService runs full-table pattern detection inside TodayView body** (judgment) — `streakStrip` triggers 6-rule trend detection with unbounded fetches on render. Real cost grows with history; see Performance.

### Medium (themes, abbreviated)
- **Rule duplication:** hydration weekday-target resolution copy-pasted in **8 files** across 3 targets (`HydrationService.swift:24-31` is the unused canonical; `StreakService`, `DailySummaryService`, `ProtocolGoalSnapshot`, `TrendAnalyticsService`, `CoachService`, `DailyProgressBars`, `HydrationComplication`). Learning-done rule written 3×, already divergent; `musicMinutes` counts toward streaks/archives but **not** milestones/achievements (`MilestoneRegistry.swift:223`, `AchievementRegistry.swift:241`).
- **Two definitions of "complete day":** `StreakService` protocol streak = fasting+hydration only (with a stale "for now" comment); `DailySummaryService.todayProtocol` scores 4 domains. `TodayView` shows both as "the master metric." Streak can advance while the tally reads 2/4.
- **Watch complications pin `Asia/Tokyo`** (`HydrationComplication.swift:80,91`, `FastCountdownTimelineProvider.swift:76`, `MascotComplication.swift:48`) while the app follows the device tz via `UserCalendar`. Wrong-day on travel.
- **"Stay pinned" travel option is wired to nothing** — `RootView` alert + `SettingsView:299` toggle set `travelModeFollowsDevice`, but `UserCalendar.timezone` ignores it.
- **Four single-row `DailyLog` fetches miss `supersededAt == nil`** and can return a neutralized tombstone (the same class the recent fix addressed; a few remain).
- **Cold launch runs a 31-day archive backfill** with 3 unbounded fetches + a CloudKit write; `DailyProgressBars` holds **7 unbounded `@Query`** (one unused).
- **Docs drift:** `CLAUDE.md` File Layout + milestone plan describe a pre-engagement project (verified, downgraded to Medium); `README.md` frozen at May 5; `ARCHITECTURE.md` still lists the removed Widgets extension; `<YOUR-TEAM>` placeholders remain; decision IDs collide with no index; 7 root docs are `chmod 400`.
- **Guard scripts not invoked:** `scripts/check_schema_parity.sh`, `check_assets.sh` exist but nothing runs them. `TESTING.md` documents a GitHub Actions workflow that never existed.

### Low (selected)
~18 `try?` sites missing the mandated justification comment; dead code (`OnDeviceShortTextProvider`/`ShortTextGenerating`, unused `IdentityCopy` entries, an orphan `.learning` Handoff receiver); `jstCalendar()` helper misnamed in 7/8 copies; ISO-weekday conversion duplicated 16×; user-entered fast-break reason logged `privacy: .public`; dead availability guards below the iOS 18 floor; `.work/state.json` stale.

### Strengths (preserve these)
- Non-destructive retention is genuinely honored (tombstones, no timer-path deletes); the `PersistenceBootstrap` recovery ladder is real and tested.
- Timezone is centralized in `UserCalendar` on the phone (the complications are the only stragglers).
- The container-retention test hazard from prior sessions is **fully remediated** — 0 inline `make().mainContext` sites remain.
- Tests assert behavior, not just execution (sampled); closure-injectable seams for HealthKit/ActivityKit/CloudKit keep them device-free.
- Typed `LocalizedError`s, `os.Logger` with privacy annotations, justified `try?` as the norm, zero force-unwraps outside tests/previews.

## Improvement Strategy

**Theme 1 — One rule, one place.** Most Medium findings are the same root cause: business rules (hydration target, learning-done, day-complete, ISO weekday) are re-implemented per call site and have drifted. Target state: each rule is a single pure function/extension in a shared file every target compiles; call sites reference it. Done = grep finds one definition each; the watch, complication, and phone agree on the same day.

**Theme 2 — The snapshot is the tally.** `ProtocolGoalSnapshot` already is the parity guarantee; make every glanceable surface use it (it is missing only on the watch app). Done = `IdleHomeWatchView` has no `todayTally`; 0 hand-rolled tallies remain.

**Theme 3 — Make the green bar real.** The 662-test gate is aspirational. Target: a CI job (or local pre-push hook) runs the suite + schema-parity + asset guard. Done = a red suite blocks merge.

**Theme 4 — Docs tell the truth.** Root docs describe a project two milestones stale. Target: `README`/`CLAUDE.md`/`ARCHITECTURE.md` match the shipped app; one decision index. Done = a fresh-machine rebuild is possible from docs alone.

**Explicitly NOT recommending:** adding any dependency (constraint); a SwiftLint config (review-only enforcement is adequate at this maturity, but the style mandate in CLAUDE.md should be softened to match); breaking `TodayView`/`CoachService` into many files purely for size (real but low payoff vs. risk for a solo maintainer); reintroducing a pinned home timezone (it was removed deliberately — wire the toggle off or remove it).
