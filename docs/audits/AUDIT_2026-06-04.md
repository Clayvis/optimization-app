# Codebase Audit — 2026-06-04

Scope: full static sweep of the iOS + watchOS targets for (1) Swift 6 / Release-archive
concurrency hazards, (2) retention-rule and data-correctness issues, (3) CLAUDE.md
convention and correctness bugs, (4) performance against PERFORMANCE.md. No compiler was
available in the audit environment, so every claim is from source reading + grep, and the
applied fixes are pattern-matched to existing, proven code in this repo.

## Headline

- Concurrency: after the earlier `NotificationService` fix, no additional
  will-fail-archive `Sending '...' risks causing data races` site was found. The one item
  flagged by tooling (`SessionLifecycleService`) uses `nonisolated(unsafe)`, which is an
  explicit compiler opt-out and therefore compiles; it is a latent runtime race, not a
  build blocker.
- Retention: clean. Every `modelContext.delete(` is on an allowed user-action path. The
  non-destructive `DailyLog` dedupe is verified correct: `DailyLogStore.neutralize()` nils
  or zeroes every measurement field, so retained tombstones contribute zero to every
  aggregate. The "critical tombstone data-corruption" the automated sweep reported is not
  real; the design guarantee holds.
- Performance: the real win. `StreakService` and `LearningService` were fetching every
  `DailyLog` ever written (unbounded, forever-growing) and running on every log. The M3.5
  in-the-moment-feedback work (this session's P0) amplified that by recomputing all streak
  domains immediately on each log. Fixed below.

## Fixes applied this pass

1. `StreakService.buildCompletionHistory` (StreakService.swift:235–288). Bounded all six
   fetches to the existing 730-day `earliest` window and added `supersededAt == nil` to the
   `DailyLog` fetches. Was: `FetchDescriptor<DailyLog>()` (whole table) ×4 plus unbounded
   `WorkoutEvent` and `FreezeApplication`. Now date-bounded via `#Predicate`. All-time
   `longestStreak` is preserved because the counter stores it monotonically
   (`max(counter.longestStreak, longest)`), so bounding the input cannot shrink it.

2. `LearningService.recomputeStreak` (LearningService.swift:35). Added `supersededAt == nil`
   to the `DailyLog` fetch. Removes tombstone-vs-canonical duplicate-date ambiguity in the
   streak history; `totalMinutesAllTime` semantics preserved (no date bound applied here).

3. `LapseDetectionService.recompute` (LapseDetectionService.swift:45–50). Pushed the 30-day
   lookback into a `#Predicate` instead of fetching all `ActivityArchive` rows and filtering
   in memory.

4. `FastingView` (FastingView.swift:99). Removed the `reason!` force-unwrap
   (`reason.map { "(\($0))" } ?? ""`), per the no-force-unwrap rule.

These mirror predicate usage already proven in `DailyLogStore.swift:38` and
`DailySummaryService.swift:72`. Build and run the test suite to confirm; the only behavioral
change is that streak history now considers the last 730 days, which is the lookback the
algorithm already used.

## Not yet fixed — recommended, in priority order

### P1 performance (apply with a build + test cycle)

- `ReactiveRecomputeService.run()` recomputes all four streak domains synchronously on the
  main actor on every `.userStateChanged` (every log). With the fetches now bounded this is
  far cheaper, but consider coalescing rapid logs (a short debounce) so back-to-back taps do
  not each trigger four recomputes.
- `ActivityArchiveService.rollupDay` (ActivityArchiveService.swift:115, 120, 137). Three
  unbounded fetches (`WorkoutEvent`, `LiftSession`, `CharacterStateLog`) filtered in memory;
  runs up to 30× during launch backfill. Add `predicate: $0.date >= day && $0.date < tomorrow`
  (and a timestamp predicate for `CharacterStateLog`).
- `AboutView.totalSessions` (AboutView.swift:35–44). Four unbounded count fetches inside a
  computed property re-evaluated on every render. Cache in `@State` via `.task`, or use a
  count-only fetch.
- `NextBlockCard` (NextBlockCard.swift:54, 71). Constructs a new `ScheduleService` twice per
  60-second tick just to call `minutesFromMidnight`. Reuse the cached service or make that a
  static helper.

### P2 correctness / robustness (low severity)

- `RecoveryGate.sevenDayBaseline` (RecoveryGate.swift:111) and
  `ActivityArchiveService.nearestHistoricalDate` (ActivityArchiveService.swift:161). Add
  `supersededAt == nil` for clarity and a marginal perf gain. Currently SAFE because
  `neutralize()` nils the fields these read; defensive only.
- `TrendAnalyticsService` (TrendAnalyticsService.swift:531). `end.addingTimeInterval(86399)`
  to reach end-of-day is DST/leap-second fragile; use `Calendar.date(byAdding: .day, value: 1, ...)`.
- `SessionLifecycleService` (SessionLifecycleService.swift:30, 56). `nonisolated(unsafe) var
  lastDispatchedTask` written from a nonisolated function. Compiles (explicit opt-out) but is
  a latent data race; the field exists only so tests can await the dispatched work. Isolate
  it to `@MainActor` or guard it, or gate it behind `#if DEBUG`.

### P3 conventions / cleanup (not bugs)

- `try?` justification: 221 `try?` uses vs 123 justification comments in production, so
  roughly 98 `try?` lack the required `// MARK: - try? justified because ...` comment. Audit
  and annotate (or restructure to typed `do/catch`).
- `@escaping` (27 occurrences): all the ones reviewed are framework-required callbacks
  (WidgetKit timelines, `HKLiveWorkoutBuilder` delegates, `UNUserNotificationCenter`). The
  CLAUDE.md ban targets new app-internal completion handlers; these are acceptable. Confirm
  none are new internal APIs.
- `WatchConnectivityService` `@unchecked Sendable` test-only mutable state: `#if DEBUG`-gated;
  document the single-thread assumption or guard with a lock.

## Corrections to the automated sweep

The parallel agents over-stated three items; the truth after reading the source:

- "Four critical tombstone data-corruption bugs, fix immediately" — not real.
  `DailyLogStore.neutralize()` nils/zeroes every field, so tombstones fail every threshold
  check and are `compactMap`-dropped from every average. Aggregates are correct today.
- "`SessionLifecycleService` will fail the archive" — it will not; `nonisolated(unsafe)`
  suppresses the diagnostic. Latent race only.
- "`CharacterStateService` unbounded `StreakCounter` fetch is critical" — negligible;
  `StreakCounter` holds at most five rows (one per domain), ever.

## Posture

Concurrency is clean post-fix with no further archive blockers found; retention is fully
respected and the dedupe is verified non-destructive; the meaningful improvements were the
hot-path fetch bounding (done) plus the P1 items above. Nothing found rises to data loss.
