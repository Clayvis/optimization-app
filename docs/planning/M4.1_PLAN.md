# M4.1_PLAN.md

Implementation plan for `M4.1_SPEC.md`. 18 tasks across 4 blocks. Estimated 14-20 hours of agent execution.

Workflow rule (memorized preference): commit each task atomically, push directly to `main`. No per-task branches. Build + test before each push.

---

## Block 1 — Schema + foundation (3-4 hours)

Foundation pieces that everything else builds on. Get these right and the rest is mechanical.

**T1. SchemaV9 + lightweight migration.**
- New file: `PersonalOptimization/Models/SchemaV9.swift`.
- Append SchemaV9 enum, identical to V8's model list + `ScheduleGenerationRun.self`.
- Update `AppMigrationPlan` (in same file as SchemaV2/V3/etc.) to include V9 with `.lightweight(fromVersion: SchemaV8, toVersion: SchemaV9)`.
- Update `PersonalOptimizationApp.swift` and `RootView.swift` previewContainer to `Schema(versionedSchema: SchemaV9.self)`.
- Tests: V8 → V9 migration preserves existing data, new fields default correctly.

**T2. ScheduleBlock anchor fields.**
- Edit `PersonalOptimization/Models/ScheduleBlock.swift`.
- Add `var anchorEvent: String?` and `var anchorOffsetMinutes: Int?` with defaults nil.
- Update `init` to accept them as optional parameters with nil defaults.
- Tests: round-trip persistence of anchor fields; backwards compat (existing seeded blocks have nil anchors).

**T3. UserProfile anchor list + generation timestamp.**
- Edit `PersonalOptimization/Models/UserProfile.swift`.
- Add `var anchorEventsCSV: String = ""` and `var lastGeneratedAt: Date?`.
- Helper computed property: `var anchorEvents: [String]` parses CSV.
- Tests: round-trip; empty CSV produces empty array.

**T4. ScheduleGenerationRun model.**
- New file: `PersonalOptimization/Models/ScheduleGenerationRun.swift`.
- Model per SPEC § Data model.
- Helper enum `ScheduleGenerationRunStatus { case proposed, accepted, discarded }` with raw string mirror.
- Auto-purge helper static func that deletes rows older than 30 days; called once per app launch.
- Tests: persistence, purge of old rows.

**T5. ScheduleValidator (pure-Swift).**
- New file: `PersonalOptimization/Modules/Schedule/ScheduleValidator.swift`.
- Public surface:
  ```swift
  enum ScheduleValidationError: LocalizedError {
      case overlap(blockA: Int, blockB: Int, day: Int)
      case sleepWindowIntersect(blockIndex: Int)
      case weeklyVolumeExceeded(domain: String, count: Int, max: Int)
      case invalidModule(blockIndex: Int, value: String)
      case invalidAnchor(blockIndex: Int, value: String)
      case invalidWeekday(blockIndex: Int, value: Int)
  }

  struct ScheduleConstraints {
      let sleepWindowStartHour: Int   // 22 default
      let sleepWindowEndHour: Int     // 6 default
      let weeklyLiftMax: Int          // 6 default
      let knownModules: Set<String>
      let knownAnchors: Set<String>
  }

  enum ScheduleValidator {
      static func validate(_ blocks: [ScheduleBlockDraft], against constraints: ScheduleConstraints) throws
      static func summarize(_ errors: [ScheduleValidationError]) -> String  // for prompt-feedback retry
  }
  ```
- Pure value-in, errors-out. No SwiftData, no I/O.
- Tests: 12 unit tests, one per failure class plus happy path with realistic schedules.

**Dependencies:** T1 → T2, T3, T4 (schema must exist first). T5 has no deps.

## Block 2 — Generation pipeline (4-5 hours)

The new AI path. End-to-end: user opens form, Claude returns a draft, user previews diff, applies.

**T6. ScheduleBlockDraft + GenerationProposal DTOs.**
- New file: `PersonalOptimization/Modules/Schedule/AI/ScheduleGenerationDTO.swift`.
- Codable structs matching the JSON Schema in SPEC § Generation pipeline.
- `func toScheduleBlock() -> ScheduleBlock` on the draft for one-line conversion at apply time.
- Tests: encode + decode round-trip with realistic payloads, including null anchor fields.

**T7. CoachPrompts.generateSchedule.**
- Edit `PersonalOptimization/Modules/Engagement/CoachPrompts.swift`.
- Add `.generateSchedule` to the `CoachPrompts.Mode` enum.
- Add the system prompt body from SPEC § Prompts, wrapped in the existing XML-tag scaffold.
- Include placeholder injection points for `<user_profile>` and `<rejected_proposals>`.
- `defaultMaxTokens(for: .generateSchedule)` returns 2048 (enough for 14 blocks + rationale + warnings).
- Tests: snapshot test that the rendered system prompt for a realistic intake contains all hard constraints and the module vocabulary block.

**T8. ScheduleAIService.generate.**
- New file: `PersonalOptimization/Modules/Schedule/AI/ScheduleAIService.swift`.
- Service holds `modelContext`, `api: ClaudeAPIClient`, `memoryService: CoachMemoryService`, logger.
- Public surface:
  ```swift
  func generate(intake: ScheduleIntake) async throws -> GenerationProposal
  ```
- Implementation:
  1. Render system prompt (CoachPrompts + injected user profile + rejected memory).
  2. Render user prompt from intake.
  3. Call `api.completeJSON(model:, systemPrompt:, userPrompt:, schema:, maxTokens:)` — new helper on ClaudeAPIClient (T9).
  4. Decode → `[ScheduleBlockDraft]`.
  5. Run `ScheduleValidator.validate(_:against:)`.
  6. On validation error: ONE retry with `ScheduleValidator.summarize(errors)` appended as a user-turn message.
  7. Persist a `ScheduleGenerationRun` row regardless of accept/discard.
  8. Return `GenerationProposal { drafts, rationale, warnings, runID }`.
- Error surface: `ScheduleAIServiceError { case missingAPIKey, validationFailedAfterRetry(errors), apiFailed(underlying), decodeFailed(underlying) }`.
- Tests: mock ClaudeAPIClient; verify retry-on-validation-fail, verify run row written, verify CoachMemory rejected entries make it into the user prompt.

**T9. ClaudeAPIClient.completeJSON helper.**
- Edit `PersonalOptimization/Services/ClaudeAPIClient.swift`.
- Add `completeJSON<T: Decodable>(model:systemPrompt:userPrompt:schema:maxTokens:) async throws -> (decoded: T, response: Response)`.
- Uses Anthropic Structured Outputs via `output_config.format` with the supplied JSON Schema.
- Falls back to the existing `complete(...)` if the model is one without structured-output support (defensive; not expected for Sonnet 4.6 / Opus 4.7).
- Tests: mock URLSession; verify request body includes `output_config.format`; verify decoded result.

**T10. Apply path: ScheduleSeed.applyDrafts.**
- Edit `PersonalOptimization/Modules/Schedule/ScheduleSeed.swift`.
- Add `static func applyDrafts(_ drafts: [ScheduleBlockDraft], modelContext: ModelContext) throws` — wipes non-custom non-override blocks, inserts drafts as ScheduleBlock rows.
- Preserves `isCustom == true` rows verbatim (existing pattern from `resetToTemplate`).
- Updates `userProfile.lastGeneratedAt = Date()` and `userProfile.anchorEventsCSV` from the intake.
- Tests: apply preserves custom blocks; lastGeneratedAt updates; anchor CSV stored.

**Dependencies:** T6 → T8 (DTOs first). T7 → T8 (prompt before service). T9 → T8 (API helper before service). T10 → T13 (apply before view that calls it). T5 → T8 (validator before service).

## Block 3 — Views + UX (4-5 hours)

User-facing surface. Build the three new views, wire into onboarding and settings.

**T11. ScheduleIntake form data + ScheduleGenerationView.**
- New file: `PersonalOptimization/Views/Schedule/AI/ScheduleGenerationView.swift`.
- Local `ScheduleIntake` struct with all form fields (Codable so it persists into ScheduleGenerationRun.intakeJSON).
- Three-section Form per SPEC § UX → Generation form.
- Bottom CTA: "Generate" calls `ScheduleAIService.generate(intake:)` in a Task; shows a progress overlay while in-flight; on success pushes `ScheduleDiffView`.
- Cancel + retry handling.
- Tests: snapshot test (light + dark, default size); intake serialization round-trip.

**T12. ScheduleDiffView.**
- New file: `PersonalOptimization/Views/Schedule/AI/ScheduleDiffView.swift`.
- Reads current schedule via `@Query`, takes proposed `[ScheduleBlockDraft]` as input.
- Diff computation pure-Swift helper that buckets each block into `.added / .removed / .modified / .unchanged`.
- Visual: stacked weeks (sequential, not side-by-side, for iPhone width). Each day is a section header; blocks within are tagged with the colored indicator.
- Footer: "Apply all" (primary), "Edit per block" (pushes a list), "Discard" (destructive).
- Tests: diff helper unit tests; apply writes correct ScheduleBlock rows.

**T13. Onboarding integration.**
- Edit `PersonalOptimization/Views/OnboardingView.swift` schedule step.
- Add the "Build me a schedule (AI)" tile at top of the templates list.
- Tapping pushes ScheduleGenerationView modally; on dismiss with success, advances onboarding to wrap-up.
- On dismiss without success (cancel or discard), user returns to template list.
- Tests: UI test stub (verify tile present and tappable).

**T14. Settings entry + lastGeneratedAt surface.**
- Edit `PersonalOptimization/Views/SettingsView.swift` (Schedule section).
- Add "Generate with AI" button next to the existing "Schedule templates" entry.
- Show "Last generated: <relative date>" when `lastGeneratedAt != nil`.
- Soft confirmation dialog if regenerating within 24h: "you generated recently; this will replace the current schedule. Continue?".
- Tests: visibility of last-generated timestamp.

**Dependencies:** T11 → T12 (form pushes diff). T12 → T13, T14 (entry points push diff). T10 → T12 (diff applies via T10).

## Verification

End-to-end smoke tests (manual, on the iPhone 17 Pro simulator):

1. **Fresh-install wife flow.** Erase sim. Launch app. Complete onboarding via the AI path with intake: goal=strength, training days=Mon/Wed/Fri evenings, anchor="after kid bedtime", no injuries. Verify: diff view shows ~5 generated blocks, "Apply all" lands on TodayView with the wife's schedule (not Clay's). Quit, relaunch, schedule persists.

2. **Clay regeneration.** Open the existing install (Clay's CloudKit-backed data). Settings → Schedule → Generate with AI. Intake: goal=balanced, anchors=after-kid-dropoff + after-coffee. Verify: diff view shows current schedule on left/top, proposed on right/bottom, isCustom blocks (if any) untouched in both. Apply replaces non-custom blocks only.

3. **Adaptation cycle with rejection.** Erase sim, seed 3 weeks of fake adherence data (use a debug helper if shipped, otherwise log manually). Run `CoachService.suggestScheduleOptimizations` from a debug menu. Get a suggestion. Dismiss. Run again — confirm the same suggestion does NOT come back.

4. **Validator catches violations.** Manually edit a generated block in the per-block editor to overlap another block. Verify a non-blocking warning appears with the offending block flagged.

5. **Build + test gate.** `xcodegen` is NOT run during this phase (per the regeneration hazard noted in M3.8 / M4.1 commit history); pbxproj edits done by hand for new files, mirroring the M3.7 pattern. `xcodebuild test -scheme PersonalOptimization -destination 'platform=iOS Simulator,name=iPhone 17 Pro'` passes with 0 failures.

## Risk register

| Risk | Likelihood | Mitigation |
|---|---|---|
| Anthropic Structured Outputs grammar compile latency hurts first-call UX | Medium | Cache the JSON Schema; pre-compile on first launch in a background Task; show "thinking..." with a 15s expected duration in the form |
| Validator retry can't fix subtle errors (e.g., "missing recovery block") | Low-medium | Surface warnings to the user in the diff view; do not block apply on soft warnings |
| Memory of rejected proposals balloons over time | Low | 60-day expiry on entries; CoachMemoryService.active already auto-prunes |
| Onboarding flow becomes too long with the new step | Medium | AI tile is the FIRST option; tapping skips the static template grid; users not interested see the static grid unchanged |
| pbxproj hand-edits regress | Low | Mirror the M3.7 close-note pattern: validate by running `xcodebuild build` after each new-file insertion; ScheduleSeedTests.resourceBundle() pattern works as a probe |
