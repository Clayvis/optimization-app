# docs/

Project documentation. Bootstrap-critical specs stay at the repo root because
CLAUDE.md reads them at the start of every session; archival and reference
material lives here.

## Stays at root (read by CLAUDE.md bootstrap)

`README.md`, `CLAUDE.md`, `PROJECT_BRIEF.md`, `ARCHITECTURE.md`,
`DATA_MODELS.md`, `MILESTONES.md`, `PERFORMANCE.md`, `TESTING.md`,
`SECURITY.md`, `PIVOT_SPEC.md`, `BOOTSTRAP.md`.

## docs/planning/

Milestone specs and historical execution plans: the M3.6 / M3.7 / M3_7a / M4.1
specs and plans, `IMPROVEMENT_IMPLEMENTATION_PLAN.md`,
`LAUNCH_SCHEDULE_AND_GAPS_PLAN.md`, `HANDOFF_CLAUDE_CODE.md`.

## docs/product/

Product context: `PROJECT_OVERVIEW.md`, `V1_OPPORTUNITIES.md`.

## docs/audits/

Point-in-time code audits (e.g. `AUDIT_2026-06-04.md`).

## docs/design/

Design assets: `Mascot.svg`, `chiba.svg`.

## docs/roadmap/

Responsive product-roadmap web page covering shipped capabilities, current
improvement priorities, future features, and the product decision rules. Open
`roadmap/index.html` directly or serve `docs/` as the GitHub Pages source.

## References/ (unchanged, repo root)

Validated logic and seed data the build/milestones consume directly
(`biomarker-tracker.html`, `default_schedule.json`, `sample_lab_dod.json`,
`character_brief.md`, `gemini_workflow.md`). Left in place because CLAUDE.md and
milestone code reference these paths.
