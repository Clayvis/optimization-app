## Bug Root Cause (verified via runtime logs)

End-session buttons (fast, basketball, lift, swim) fail because **HealthKit state machine errors poison local session state**. Runtime logs show:

```
Ended basketball session, achilles=5
HKWorkoutBuilder_AC43: Failed to update target construction state:
Error(7) state (event 1)
```

The SwiftData write succeeds (session logged), but the HKWorkoutBuilder is stuck in error state. UI continues showing the session as active because it observes HK state, not SwiftData state. Live Activities have the same bug. User taps end repeatedly, sees no change, abandons the session.

**Architectural fix (load-bearing for M3.6):**

SwiftData is the authoritative source of truth for "is this session active?" HealthKit is a best-effort secondary write. End-session always succeeds locally regardless of HK status. HK writes happen async with bounded retry; failures are logged but never block UI updates. Live Activities observe SwiftData session state, not HK workout builder state.

This same pattern almost certainly breaks lift, swim, learning sessions too. Audit all session lifecycle code.

## M3.6 Tasks

### Block 1: Bug fixes (8-10 hours)

**Task 1: SessionLifecycleService refactor**

Centralize session start/end logic across all training modules behind one service. Pattern:

```
struct SessionLifecycleService {
    func start(domain: TrainingDomain, modelContext: ModelContext) -> StartResult
    func end(sessionID: UUID, modelContext: ModelContext) -> EndResult
    private func writeHealthKitWorkout(...) async  // fire-and-forget
}
```

SwiftData writes happen synchronously and always succeed (assuming valid context). HealthKit writes go through a separate async path with retry-on-failure (max 3 attempts, exponential backoff). HK failures log to OSLog and write a `HealthKitWriteFailure` row for later retry. They do NOT block UI.

Audit and migrate:
- FastingService.endFast (the early-break button)
- BasketballService.endSession
- LiftService.endSession
- SwimService.endSession
- LearningService.endSession (if it has a session lifecycle)

**Task 2: Live Activity observers**

Audit FastingLiveActivity and WorkoutLiveActivity. They must observe the SwiftData session entity (via @Query or NSFetchedResultsController-equivalent), not HKWorkoutBuilder state. When session.endTime is set, Live Activity dismisses immediately.

End-of-session should call `Activity.end(_:dismissalPolicy: .immediate)` synchronously inside SessionLifecycleService.end().

**Task 3: HealthKit error state handling**

Wrap all HKWorkoutBuilder calls in do/catch. On error, log to OSLog with category "healthkit", write HealthKitWriteFailure row, return cleanly. Never throw from session-end paths.

Add a Settings -> Diagnostics view showing recent HealthKit failures so user can see when sync is failing.

**Task 4: Tests**

Regression tests that fail in current code, pass after fix:
- End fasting early without HK auth → SwiftData session marked complete, mascot updates, Live Activity dismissed, no crash.
- End basketball session with HK in error state → same.
- End lift session with HK auth revoked mid-session → same.
- End swim with HK builder failure → same.

Total: 8-12 tests.

### Block 4: Coach Mode (4-6 hours)

**Task 15: CoachService**

New service. One Claude API call per day per user, cached for 24 hours. Manual refresh available.

```
final class CoachService {
    func generateDailyInsight(for userProfile: UserProfile) async -> CoachInsight
    func refreshInsight() async -> CoachInsight  // manual override
    private func gatherContext() -> CoachContext  // SwiftData + HealthKit
}
```

CoachContext aggregates:
- Today's protocol adherence number
- Last 7 days workout history (count, types, volume)
- Current streaks across all domains
- Last 24h fasting status (active or last completion)
- Last 24h hydration (oz, target met)
- Mascot current state
- HealthKit today: steps, active calories, exercise minutes, resting HR, sleep last night
- User's motivationStyle preference (added in Task 17)

System prompt (locked, configurable per user style):
```
You are a holistic optimizer combining the perspectives of a strength coach,
nutritionist, and life coach. Read the user's day-in-context and produce
ONE concise insight (max 80 words).

Style: {stoic|holistic|warrior|spiritual|scientific|balanced}.

Rules:
- No filler. No motivational platitudes. No em dashes.
- Anchor advice to specific data points from the context.
- Identity framing: speak to who they are, not what they did.
- One actionable nudge, max.
- If their data shows they need rest, prescribe rest.
```

API call uses Sonnet 4.6 by default. Logs token usage to OSLog category "coach" for cost tracking.

**Task 16: CoachInsight model**

```
@Model final class CoachInsight {
    var generatedAt: Date
    var insightText: String
    var contextSummary: String  // for debugging
    var tokenUsage: Int
    var refreshCount: Int  // 0 = morning auto, 1+ = manual refreshes
}
```

Cache rule: if a CoachInsight from the last 24 hours exists, use it. If user manually refreshes, generate new one and increment refreshCount on the existing row OR create a new row with refreshCount tracking the day's count.

**Task 17: UserProfile.motivationStyle**

Add field: `motivationStyle: String` with default "balanced". Allowed values: stoic, holistic, warrior, spiritual, scientific, balanced, custom. Onboarding (M4) lets user pick. M3.6 ships the field with default + Settings toggle to change it.

If "custom" is selected, an additional field `customStylePrompt: String?` holds user-supplied style notes (e.g., "speak like a Marcus Aurelius quote with practical action steps").

**Task 18: Today tab CoachInsightCard**

New view component on TodayView. Sits below the master metric, above the schedule blocks.

- Card shows: mascot avatar (small, 60x60 cropped face), insight text, generated timestamp ("2 hours ago"), refresh button.
- Tap card to expand into full sheet showing the context summary and recent insights history.
- If API key not set in Keychain, card shows: "Set your API key in Settings to enable Coach Mode" with link.
- If insight generation fails (network, API error), card shows last cached insight with timestamp + retry button.

**Task 19: Daily quote (lighter Coach companion)**

Separate from CoachInsight. Small Haiku call (cheap, ~$0.005). One quote per day in user's motivationStyle. Displayed at top of TodayView header in small italic text under the date.

Examples by style:
- Stoic: Marcus Aurelius, Seneca, Epictetus pull-quotes. Either curated database OR Haiku-generated.
- Warrior: Bushido, Sun Tzu, Goggins-style intensity.
- Holistic: balance, breath, presence.
- Scientific: research-backed factoids about training/recovery/longevity.

Implement as: curated database (free, ~50 quotes per style) for v1, with optional Haiku fallback if user enables "AI-generated quotes" in Settings.

**Task 20: Coach tests**

- CoachContext gathers correctly with empty data, partial data, full data.
- Cache hit returns existing insight without API call.
- Manual refresh forces new API call.
- API failure falls back to last cached.
- Style prompt selection produces different output.

### Block 5: Polish (1-2 hours)

**Task 21: Suppress simulator-only noise**

The CHHapticPattern errors and IOSurfaceClientSetSurfaceNotify warnings only fire on simulator. Wrap haptic calls in:

```
#if !targetEnvironment(simulator)
HapticEngine.play(...)
#endif
```

Or fall back to UIImpactFeedbackGenerator when CHHapticPattern fails. Either approach is acceptable; choose whichever the existing haptic abstraction makes cleaner.
